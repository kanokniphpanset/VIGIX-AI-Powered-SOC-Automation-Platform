## 3. สคริปต์เปิด (อ่านให้ผู้ทดสอบฟัง)

> "วันนี้เราทดสอบ **ระบบ** ไม่ได้ทดสอบคุณ ถ้าทำไม่ได้แปลว่าระบบต้องปรับ ไม่ใช่คุณผิด
> ระหว่างทำ ช่วยพูดสิ่งที่คิดออกมาดังๆ เช่น 'กำลังหาปุ่ม…' 'ไม่แน่ใจว่าคำนี้แปลว่าอะไร'
> ผมจะไม่ช่วยระหว่างทำงาน ถ้าติดจริงๆ บอกได้ว่า 'ขอความช่วยเหลือ' แล้วผมจะบอกใบ้ (จะนับว่าขอความช่วยเหลือ 1 ครั้ง)
> ข้อมูลทั้งหมดเป็นข้อมูลทดสอบ กดอะไรก็ได้ไม่มีผลกับระบบจริง"

เมื่อทัวร์แนะนำขึ้นมาเอง: **ไม่ต้องพูดอะไร** — สังเกตว่าอ่านจบไหม หรือกดข้าม

## 4. งานทดสอบ 3 งาน

ทุกงานเริ่มที่หน้า **ภาพรวม** · อ่านโจทย์ให้ฟังแล้ววางกระดาษโจทย์ไว้ให้ดู · เริ่มจับเวลาเมื่อผู้ทดสอบแตะเมาส์

### งาน 1 — ตรวจ Alert (บทบาท SOC)

> **โจทย์:** "มี Alert ใหม่ที่รอให้คุณตัดสิน ช่วยตรวจ Alert นั้น ถ้าดูเป็นการโจมตีจริงให้เปิดเป็น Incident ถ้าไม่ใช่ให้ปิดพร้อมเหตุผล"

| | |
|---|---|
| **สำเร็จ** | บันทึกการตัดสินได้ (Alert หายจากแท็บ Needs review) และถ้าเลือกปิด ต้องใส่เหตุผล |
| **สำเร็จบางส่วน** | บันทึกได้แต่ต้องขอความช่วยเหลือ หรือใช้เวลาเกินเป้า |
| **เป้าเวลา** | ≤ 2 นาที · ขอความช่วยเหลือ ≤ 1 ครั้ง |
| **ทางที่สั้นที่สุด** | ภาพรวม → การ์ด "Alert รอ SOC ตรวจ" → ปุ่ม **ตรวจ Alert** → Review → เลือกการตัดสิน → บันทึก |
| **สิ่งที่สังเกต** | เจอการ์ด "งานของฉันตอนนี้" ทันทีไหม · เข้าใจว่าทำไม HIGH/CRITICAL ไม่ต้องตรวจ · **อ่านข้อความผลลัพธ์ (มุมขวาล่าง) ไหม และรู้ไหมว่าขั้นต่อไปคืออะไร** |

### งาน 2 — สืบสวนจนส่งให้ IR (บทบาท SOC)

> **โจทย์:** "เปิด Incident ชื่อ **[ชื่อที่เตรียมไว้]** แล้วทำงานของ SOC ให้เสร็จ จนเคสไปถึงมือทีม IR"

| | |
|---|---|
| **สำเร็จ** | ยืนยันความรุนแรง → Run AI Analysis → สร้าง Recommendation → ส่งให้ IR ครบ (การ์ด "ขั้นต่อไป" เปลี่ยนเป็น "ถึงตา IR") |
| **สำเร็จบางส่วน** | ส่งให้ IR ได้แต่ข้ามการยืนยันความรุนแรง หรือต้องขอความช่วยเหลือ |
| **เป้าเวลา** | ≤ 6 นาที (ไม่นับเวลารอ AI ประมาณ 1 นาทีต่อครั้ง) · ขอความช่วยเหลือ ≤ 1 ครั้ง |
| **ทางที่สั้นที่สุด** | กดปุ่มในการ์ด **ขั้นต่อไป** 4 ครั้ง (ยืนยันความรุนแรง → Run AI Analysis → สร้าง Recommendation → เปิด Recommendation แล้วกด Send to IR) |
| **สิ่งที่สังเกต** | ใช้การ์ด "ขั้นต่อไป" หรือเดาจากแท็บ · เข้าใจว่า AI **ไม่ได้** กำหนดความรุนแรง · รู้ไหมว่างานของ SOC จบแล้วหลังส่ง |

### งาน 3 — ตัดสินใจและลงมือ (บทบาท IR)

> **โจทย์:** "มี Ticket ที่รอให้คุณตัดสินใจ ถ้าเห็นด้วยกับแผน ให้อนุมัติแล้วลงมือจนถึงขั้นตรวจยืนยันผล แล้วบอกผมว่าผลคืออะไร และเคสจะเป็นอย่างไรต่อ"

| | |
|---|---|
| **สำเร็จ** | อนุมัติ (พร้อมเหตุผล) → เริ่มดำเนินการ → ทำ Checklist → ทำเสร็จแล้ว → Re-hunt และ **อธิบายผลได้ถูก** ("ไม่พบภัย = เคสแก้ไขแล้ว" หรือ "ยังพบภัย = กลับไปสืบสวนรอบใหม่") |
| **สำเร็จบางส่วน** | ทำครบแต่ตีความผล Re-hunt ผิด หรือต้องขอความช่วยเหลือ |
| **เป้าเวลา** | ≤ 5 นาที · ขอความช่วยเหลือ ≤ 1 ครั้ง |
| **ทางที่สั้นที่สุด** | ภาพรวม → การ์ด "รอ IR ตัดสินใจ" → **ตัดสินใจ** → เปิด Ticket → ใส่เหตุผล → **Approve** → **Start response** → ติ๊ก Checklist → **Mark eradicated** → **Run re-hunt** |
| **สิ่งที่สังเกต** | รู้ไหมว่าต้องใส่เหตุผลก่อนกด · อ่านข้อความ "ขั้นต่อไป" หลังแต่ละปุ่มไหม · เข้าใจคำว่า Re-hunt (ใช้ปุ่ม (?) ไหม) |

> หมายเหตุ: ในระบบทดสอบ ผล Re-hunt อาจออกได้ทั้งสองแบบ — วัดที่ **การตีความผลถูกต้อง** ไม่ใช่ผลที่ได้

### คำถามปิดท้ายสั้นๆ (ไม่นับเป็นงาน)

1. "ถ้าอยากให้หน้าจอเป็นภาษาอังกฤษ จะทำอย่างไร" — สำเร็จเมื่อกดปุ่ม **EN** ได้ภายใน 20 วินาที
2. "ถ้าลืมวิธีใช้ จะดูคำแนะนำอีกครั้งได้ที่ไหน" — สำเร็จเมื่อกดปุ่ม **(?)** แล้วพบ "เริ่มทัวร์แนะนำอีกครั้ง"

## 7. แบบสอบถาม SUS (System Usability Scale) — หลังจบทุกงาน

ให้คะแนน 1 = ไม่เห็นด้วยอย่างยิ่ง … 5 = เห็นด้วยอย่างยิ่ง

1. ฉันคิดว่าฉันอยากใช้ระบบนี้บ่อยๆ
2. ฉันรู้สึกว่าระบบนี้ซับซ้อนเกินจำเป็น
3. ฉันคิดว่าระบบนี้ใช้งานง่าย
4. ฉันคิดว่าต้องมีคนที่รู้เรื่องเทคนิคช่วย ฉันจึงจะใช้ระบบนี้ได้
5. ฉันรู้สึกว่าฟังก์ชันต่างๆ ในระบบนี้เชื่อมกันได้ดี
6. ฉันรู้สึกว่าระบบนี้ไม่สม่ำเสมอ (สิ่งเดียวกันแต่แสดงไม่เหมือนกัน) มากเกินไป
7. ฉันคิดว่าคนส่วนใหญ่จะเรียนรู้การใช้ระบบนี้ได้เร็วมาก
8. ฉันรู้สึกว่าระบบนี้ใช้ยุ่งยาก
9. ฉันมั่นใจมากในตอนที่ใช้ระบบนี้
10. ฉันต้องเรียนรู้หลายอย่างก่อนจะเริ่มใช้ระบบนี้ได้

**วิธีคิดคะแนน:** ข้อคี่ (1,3,5,7,9) = คะแนน − 1 · ข้อคู่ (2,4,6,8,10) = 5 − คะแนน · รวม 10 ข้อแล้ว × 2.5 → 0–100
(ค่าเฉลี่ยทั่วไปของระบบซอฟต์แวร์ ≈ 68)

**คำถามปลายเปิด 3 ข้อ**
- ตรงไหนที่ทำให้งง หรือต้องหยุดคิดนานที่สุด
- ข้อความ / การ์ดไหนที่ช่วยมากที่สุด
- ถ้าแก้ได้ 1 อย่าง อยากแก้อะไร

## 8. เกณฑ์ผ่าน

| เกณฑ์ | เป้า |
|---|---|
| อัตราทำสำเร็จ ต่องาน | ≥ 80% |
| ขอความช่วยเหลือ เฉลี่ยต่องาน | ≤ 1 ครั้ง |
| SEQ เฉลี่ย ต่องาน | ≥ 5.5 |
| SUS เฉลี่ย | ≥ 68 (เป้าหมายจริง ≥ 75) |
| ความผิดพลาดร้ายแรง | 0 ครั้ง — เช่น ส่งให้ IR โดยไม่ได้อ่าน Recommendation, อนุมัติโดยไม่ใส่เหตุผล (ระบบต้องกันได้), ตีความผล Re-hunt กลับกัน |
| คำถามปิดท้าย (EN / ทัวร์) | ≥ 4 ใน 5 คนทำได้ |

## 9. วิเคราะห์ผลและนำไปแก้

1. รวมปัญหาที่เห็นจากทุกคน แล้วให้ระดับความรุนแรง 0–4
   (0 = ไม่ใช่ปัญหา · 1 = เรื่องความสวยงาม · 2 = เล็กน้อย · 3 = ใหญ่ ควรแก้ก่อนใช้จริง · 4 = ร้ายแรง ต้องแก้ทันที)
2. ปัญหาที่เจอ ≥ 2 คน หรือระดับ ≥ 3 → แก้ก่อน
3. จับคู่ปัญหากับจุดในระบบ: การ์ด "งานของฉัน" · การ์ด "ขั้นต่อไป" · ข้อความผลลัพธ์ · ทัวร์ · คำศัพท์ / (?) · ภาษา
4. แก้แล้วทดสอบซ้ำด้วยงานเดิมกับผู้ทดสอบใหม่ 3–5 คน แล้วเทียบตัวเลขข้อ 5 กับรอบแรก

## 10. จริยธรรมและข้อมูล

- ขอความยินยอมก่อนอัดหน้าจอและเสียง · ผู้ทดสอบหยุดเมื่อไรก็ได้
- ใช้รหัส P1–P5 แทนชื่อในแบบบันทึก · ไม่เก็บข้อมูลส่วนตัวเกินจำเป็น
- ใช้เฉพาะข้อมูลทดสอบและบัญชีทดสอบ · ลบวิดีโอเมื่อวิเคราะห์เสร็จ
